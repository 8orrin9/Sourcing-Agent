## 공공 DB 5종 — 입력 키·반환 필드·함정

대부분 **사업자번호를 입력 키로** 받으므로, STEP 1·2에서 사업자번호를 확보(앵커 흡착)한 업체만 검증 가능. "②번 급소 — 이름→사업자번호 해소"가 여기서 최종적으로 걸림.

| 소스 | 입력 키 | 반환 필드 | 함정 |
| --- | --- | --- | --- |
| DART (OpenDART) | 고유번호(corp_code) ← 사업자번호/법인명 매핑 | 재무제표, 공시 | **외감 법인만** 재무 존재 → 영세 업체 공백 |
| 국세청 사업자상태 | 사업자번호 | 계속/휴업/폐업 | 이름 검색 불가 → 사업자번호 필수 |
| 국민연금 사업장 | 사업장명/사업자번호 | 가입자 수·추이, 사업장 주소 | 법인 단위 아닌 **사업장별** |
| 팩토리온 | 회사명/주소 | 공장 주소, 생산품목, 업종 | STEP 1 앵커와 동일 소스(재사용) |
| KIPRIS | 출원인/키워드 | 특허·실용신안 | STEP 1에서 이미 수집 |

### 검증은 사업자번호 확보 여부로 두 갈래

- **확보 업체** → 국세청·DART·국민연금 전부 조회 가능 → 데모의 "정상/부채비율 286%" 같은 검증값 실제 산출.
- **미확보 업체**(순수 웹 후보, 2차 흡착도 실패) → 공공 DB 조회 불가 → **감점 아닌 "현장 확인 필요" 태그**로 숏리스트에 올리되 플래그.

→ 데모 `iso:null`·`clean:null`은 "미달"이 아니라 "미확인". computeShort의 `x.iso !== 0`(null은 통과)이 이 로직을 구현.

## 인증 검증 등급 (결정)

ISO 9001 인증번호를 교차검증할 단일 공공 DB가 없음(인증기관마다 파편화, IAF CertSearch도 커버리지 부분적). 인증마다 **검증 등급을 명시**:

| 등급 | 조건 |
| --- | --- |
| **교차검증 완료** | 발급 인증기관(CB) 식별 + 해당 CB 온라인 조회로 인증번호 대조 성공 (일부만 가능) |
| **서류 확인(미교차)** | CB 조회 불가 → 인증서 PDF의 발급기관·유효기간·인증번호를 문서 Evidence로 보존 (대부분 이 등급) |
| **주장만(미검증)** | 인증서 자체 없음, 웹 언급만 |

→ "인증기관 조회 일치"는 교차검증이 되는 경우로 한정. 대부분은 서류 확인임을 정직하게 표현(감사 방어·과장 방지). **데모 문구도 이 등급 체계로 수정.**

## 하드 필터 vs 소프트 스코어 — null 처리 원칙

- **하드 필터는 "명백한 탈락"만**: 휴·폐업=제외, 자체 공장 없음=제외, 부채비율 300%↑=제외.
- **미확인(null)은 하드 필터 통과**: 데모 `x.iso !== 0`·`x.clean !== 0`. 영세 업체를 정보 부족만으로 쳐내지 않음(설계서 STEP 3 기조).
- **소프트 스코어에서도 미확인은 감점 아닌 중립** + "확인 필요" 태그로 표면화.
- 필터 임계값·스코어 가중치는 데모 기본값 사용(구매팀이 설정 파일/화면에서 조정).

## 탈락 사유 기록 (감사 대응)

탈락 업체별로 "어느 조건에서 처음 걸렸는가"(데모 `firstFail`)를 영구 보존. 하도급법·감사 방어(설계서 보안·컴플라이언스)와 직결.
