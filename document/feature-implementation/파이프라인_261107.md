# 파이프라인 — 롱리스트 → 숏리스트 오케스트레이션

작성일: 2026-11-07
상위: [아키텍처_261107.md](아키텍처_261107.md)
대상: `src/pipeline.py`, `src/llm/score.py`, `src/llm/merge.py`(dedupe_factories)

## 요약

추출기·LLM 계층을 하나의 소싱 흐름으로 엮는 오케스트레이션을 구현했다. 데모의
"외부 수집 영역"에서 벌어지는 일(후보 발견→검증→분류→스코어링→숏리스트)을 실제로
end-to-end 실행하고, 결과를 데모가 읽을 JSON으로 산출한다.

```
[discover]      확산 수집(웹검색·디렉터리·LLM폴백) → 회사명·URL 후보 롱리스트
     v
[anchor_merge]  팩토리온 앵커 조회 → 공장 중복 접기 → 확산 후보 흡착(verified 승격)
     v
[classify]      LLM: 제조사 여부 + 공정 역량(HC/AF)·증거수준
     v
[score]         규칙 기반 스펙 적합도 점수(설명가능) + 게이트(유통사·무역량 0 탈락)
     v
[shortlist]     점수순 상위 N → 결과 JSON
```

각 단계는 독립 함수라 따로 테스트·교체할 수 있고 `run()`이 체이닝한다.

## 1. 발견 (`discover`)

스펙의 `search_queries`(다국어, 공정·소재 키워드만)로 웹검색 추출기를 로케일별로 돈다.
한 쿼리 실패가 전체를 막지 않게 예외를 삼킨다. 디렉터리(2계층)·LLM폴백(4계층)은
라이브 URL이 필요해 데모에선 `longlist` 주입으로 대체(안티봇 사이트 스냅샷 재생).

## 2. 앵커 흡착 (`anchor_merge`) — 데이터 현실 교정

확산 후보의 회사명으로 팩토리온을 조회해 앵커를 만들고, LLM(`absorb_candidates`)으로
흡착한다. 흡착되면 `verified=False`(확산) → `verified=True`(앵커 검증)로 승급하고
provenances에 factorion+web_search를 누적.

### 교정: 한 기업 = 여러 공장 레코드

**라이브 검증 중 발견**: 팩토리온은 한 기업의 사업장을 각각 등록해, 같은 회사명이
주소만 다른 여러 레코드로 나온다(예: '올리콘발저스코팅코리아' 4건). 그대로 두면
숏리스트에 같은 회사가 중복 등장한다.

→ `dedupe_factories`(결정적·LLM 불필요): 정규화 회사명(`_norm_name`)이 같으면 1건으로
접고 공장 출처·notes를 누적, `[사업장 N개 통합]` 표식. `_norm_name`에 '유한회사'·㈲를
추가해 '(유)'·'유한회사' 표기 변형도 하나로 묶는다.

> 사용자 결정(261107): **회사명으로 병합** — 숏리스트를 기업 단위로 깔끔하게.

흡착 못한 잔여(앵커에 없는 해외 업체 등)도 숏리스트 후보로 남긴다(`anchors + leftover`).

## 3. LLM 분류 (`classify_all`)

각 레코드를 `classify_supplier`로 판정(제조사 여부·HC/AF 역량·증거수준). 노이즈
(특허·학회·블로그)는 여기서 trader로 걸러진다.

## 4. 스코어링 (`score.py`) — 결정적·설명가능

숏리스트 근거는 "설명 가능"해야 한다(증거 우선·HITL). 점수는 LLM이 아니라 **명시 규칙**
으로 계산하고 항목별 가점 사유(breakdown)를 함께 반환한다. LLM이 만든 건
capabilities·kind뿐이고, 그걸 스펙과 대조하는 산술은 결정적.

배점(합 100): capability 45(요청 공정×증거수준) · manufacturer 20 · verified 15(앵커
검증) · region 12(국내·선호지역) · scale 8(규모 단서).

게이트(`passed_gate`): 유통사(TRADER)이거나 요청 공정을 하나도 못 가지면 숏리스트
부적격. 존 분리: 내부 단가·현 협력사 비교는 여기 없다(숏리스트 진입 후 내부망에서).

## 5. 결과 (`run` → JSON)

`run(spec, longlist=..., live=False, top_n=6)`. longlist 주입 시 discover 생략
(오프라인·데모 재생), `live=True`면 실제 수집. 결과는 counts(롱/앵커/잔여/숏) +
shortlist(`_result_row`: 외부 공개 필드만 — 존 분리).
