# 실제 엔진 아키텍처 — 계층형 추출기 레지스트리

작성일: 2026-11-07
상위 맥락: [STEP_8_AI실행계획HITL_261107.md](../STEP_8_AI실행계획HITL_261107.md)
대상: `src/` (실제 수집·분석 엔진) — 데모(`html/`)의 "외부 수집 영역"을 실코드로 구현

## 1. 배경 — 데모에서 실제 구현으로

End Image 설계(데모)가 완료되어, 이제 데모의 "외부 수집 영역"에서 벌어지는 일
(후보 탐색·상세 수집·스코어링·회신 분석)을 **실제로 동작하는 백엔드**로 구현한다.

### 무엇을 실제로 만드는가 — 존 분리가 경계를 정한다

데모의 **외부 수집 영역 ↔ 내부망** 경계가 "실제 구현 vs 시뮬레이션"의 분기선이다.

| 구간 | 데이터 성격 | 구현 방식 |
| --- | --- | --- |
| 현황·재협상 대상·단가/품목코드 | 내부 기밀 (SDC 실데이터 불가) | **합성 mock** (`data/synthetic/`) |
| 후보 탐색·상세 수집 (롱리스트) | 공개 B2B 정보 | **실제 수집** (앵커 API + 확산 스크래핑) |
| 엔티티 병합·스코어링·회신 파싱 | LLM 추론 | **실제 LLM** (OpenAI API) |
| RFI 외부 발송 | 외부 메일 발송 (시연 불가) | **시뮬** (회신 3분기 LLM 생성) |

결정(사용자 승인): **수집 + LLM 분석까지 실제로 동작**. 기밀을 안 건드리면서
"에이전트가 진짜 전 세계에서 공급원을 찾아온다"는 가장 임팩트 있는 장면을 실연한다.

## 2. 핵심 아키텍처 — Core Engine + 비용순 Extractor Registry

```
[Core Engine]   사이트 무관 공통 (한 번만 구현)
  fetch · rate-limit · retry · robots · cache · (필요시) JS 렌더
        |
        v
[Extractor Registry]   신규 사이트 = 여기 "한 줄 등록"
  1) structured    JSON-LD/sitemap/OpenAPI   (앵커: 팩토리온·KIPRIS)
  2) config_driven YAML 셀렉터               (확산 디렉터리: 설정 한 줄)
  3) sites/*       코드 어댑터                (안티봇·복잡 JS 사이트만)
  4) llm_extract   LLM 폴백                   (설정·코드 없어도 커버)
        |
        v
[SupplierRecord]   정규화 단일 계약 — 다운스트림은 출처를 모른다
        |
        v
[LLM 계층]   엔티티 병합 → 스코어링 → 숏리스트 / 회신 파싱
```

### 왜 "사이트별 코드 한 벌"이 아니라 레지스트리인가

사이트마다 어댑터를 한 벌씩 쓰면 HTML이 바뀔 때마다 줄줄이 깨져 유지보수가 지옥이 된다.
대신 **다른 부분을 가장 싼 계층으로 흡수**한다:

- **1계층(구조화 우선)**: 디렉터리 상당수가 JSON-LD·sitemap·schema.org·OpenAPI 제공 →
  CSS 셀렉터 스크래핑보다 훨씬 안정적. 최우선.
- **2계층(선언형 설정)**: 비슷한 디렉터리는 셀렉터를 YAML로 기술 →
  신규 사이트 편입 = 코드가 아니라 **설정 파일 추가**. 롱테일을 싸게 커버.
- **3계층(코드 어댑터)**: 페이지네이션 꼼수·안티봇·복잡 JS 렌더가 있는 사이트만.
- **4계층(LLM 폴백)**: 정리한 HTML + 목표 스키마를 LLM에 주고 추출 →
  구조가 바뀌어도 견디고, **설정·코드 없는 신규 사이트를 즉시 커버**. "pool 자생 확장"의 열쇠.

### 단일 계약 — SupplierRecord (`src/schema.py`)

모든 추출기는 출처와 무관하게 이 스키마로 정규화해 출력한다. 핵심 필드:

- 식별/병합 키: `biz_reg_no`(최강)·`domain`·`address` — 앵커가 확보
- 분류: `SourceClass`(anchor/spread)·`EvidenceLevel`(L1/L2/L3)·`CompanyKind`(제조/유통)
  — 데모 개념(앵커·확산, L1~L3 증거수준, 유통사 제외) 그대로 계승
- 출처 추적: `Provenance`(소스·추출기·검증여부) — 증거 우선 원칙
- 개인정보 비저장: 연락처는 `contact_dept`·`contact_public`(부서·대표연락처)만

## 3. 사이트 pool — 데모값 진단과 매핑

데모가 상정한 소스를 실제 접근 방법 기준으로 재분류했다.

| 소스 | 구분 | 실제 접근 | 계층 |
| --- | --- | --- | --- |
| 팩토리온 공장등록 | 앵커 | 한국산업단지공단 OpenAPI (**생산정보조회**) | 1 (structured) |
| KIPRIS 특허 출원인 | 앵커 | KIPRIS Plus OpenAPI | 1 (structured) |
| EC21·고비즈코리아 | 확산 | HTML 스크래핑 | 2 (config) |
| K-Display 전시회 참가사 | 확산 | 참가사 명단 페이지 | 2 (config) |
| 다국어 웹 검색 | 확산 | Serper(Google Search) API | 별도 (검색) |
| Made-in-China 등 글로벌 | 확산 | 안티봇 강 → 픽스처 + LLM 폴백 | 3+4 |

> **진단의 함의**: 앵커 2개는 크롤링이 아니라 **공공 API**가 정답(안정·합법).
> 비용순 레지스트리에 그대로 매핑된다.

### 팩토리온 서비스 선택

한국산업단지공단 제공 두 서비스 중 **"공장등록생산정보조회서비스"** 사용.
(회사명·사업자번호·주소·생산품목 → 생산품목으로 적합성 판정 + 식별키로 엔티티 병합.)
"공장등록필지정보조회"는 토지/부동산 정보라 소싱과 무관 → 미사용.

## 4. 글로벌(중국·동남아) 시연 — 라이브 + 픽스처 하이브리드

중국 디렉터리는 안티봇이 강해 라이브 시연 중 막히면 데모가 깨진다. 해법:

```
[사전 1회]  실제 사이트 접속 → HTML 스냅샷 저장 (data/fixtures/)
[시연 당일]  추출기가 "저장된 스냅샷"에서 실제 추출 로직 실행
```

- **추출 로직은 진짜**(실데이터 파싱), 네트워크 불확실성만 제거 → 설득력 유지 + 100% 안정.
- 라이브: 국내 앵커 API(팩토리온·KIPRIS) + 다국어 웹검색(Serper) → 중화권·베트남 URL 실시간 발굴.
- 픽스처: 중국·글로벌 디렉터리 → LLM 폴백 추출기가 중문 페이지를 뽑아내는 장면 시연.
- 동남아는 데모에 이미 포함(베트남 Minh An·Dong Nai) → 웹검색 라이브로 흡착 연출.

## 5. 디렉터리 구조

```
Sourcing-Agent/
├─ html/                    # 기존 데모 (유지)
├─ src/
│  ├─ core/                 # 공통 엔진 (fetch·rate-limit·retry·cache·render)
│  ├─ schema.py             # SupplierRecord 단일 계약
│  ├─ extractors/
│  │   structured.py        #   1계층
│  │   config_driven.py     #   2계층
│  │   sites/               #   3계층 (코드 어댑터)
│  │   llm_extract.py       #   4계층 (LLM 폴백)
│  ├─ configs/              # 사이트별 YAML (2계층 데이터)
│  ├─ llm/                  # 엔티티 병합·스코어링·회신 파싱
│  └─ pipeline.py           # 롱리스트→상세→숏리스트 오케스트레이션
├─ data/
│  ├─ synthetic/            # 내부 합성 데이터 (기밀 無)
│  ├─ fixtures/             # 골든 픽스처 (추출기 회귀 테스트·글로벌 시연)
│  └─ cache/                # 크롤 캐시 (gitignore)
└─ tests/
```

추천했던 광학·코팅 소재 계열과 일치 — 공개 공급사 다수·다국어 분포·기밀 아님·2nd source 당위성 명확.

## 8. 구현 순서

1. **스캐폴딩** — 디렉터리·`schema.py`·`data/synthetic` (완료)
2. **Core Engine** — fetcher(캐시·rate-limit·robots) + 골든 픽스처 테스트 틀
3. **앵커 추출기** — 팩토리온 생산정보(1계층). KIPRIS는 익일.
4. **확산 추출기** — YAML 설정(2계층) + 글로벌 픽스처 + LLM 폴백(4계층)
5. **LLM 계층** — 엔티티 병합 → 스코어링 → 회신 파싱
6. **데모 연동** — 파이프라인 결과(JSON)를 데모가 읽도록 연결

## 9. 보존 원칙 (데모 4원칙 계승)

- **존 분리**: 외부 수집·RFI에 내부 단가·내부 품목코드·현 협력사명 미포함
- **사람 확인 지점**: 자동 조치는 제안→승인 (HITL), 화면 전환은 사람
- **개인정보 비저장**: 부서·대표 연락처만
- **ERP 쓰기 제외**: 등록은 "표시"까지
- **증거 우선**: 모든 값은 Provenance로 출처 추적
