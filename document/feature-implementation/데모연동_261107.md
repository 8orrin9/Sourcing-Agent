## 왜 증거 콘솔 분리인가

데모 SUP은 caps 6종·docs·staff 시계열·flags까지 짜인 완결 내러티브라, 구조·업체가
다른 파이프라인 실결과(올리콘발저스코팅 77점 등)로 덮으면 시연 스토리가 깨진다. 대신
"방금 본 흐름을 실제 엔진이 돌리면 이렇게 나온다"를 **롱리스트 화면 하단 콘솔**에 붙여,
mock 시연과 실데이터 검증을 공존시킨다.

## 붙이는 위치

롱리스트 화면(`s-long`) — 화면 설명이 이미 "다국어 웹검색·B2B 디렉터리·공장등록 통합
조회"라 파이프라인이 한 일과 정확히 대응. `#longNext`(상세수집 전진 버튼) 위에
`#longEvidence` 카드를 추가, `runLong()` 완료 후 렌더.

## 데이터 계약 (파이프라인 JSON → 데모)

`data/output/shortlist_SR-2026-1025-014.json`의 필드를 그대로 쓴다(별도 변환 없음):

| JSON 필드 | 콘솔 표시 |
| --- | --- |
| `counts` {longlist, anchored, leftover, shortlist} | 상단 요약 수치 |
| `shortlist[].name` / `region` / `country` | 업체명 · 소재지 |
| `shortlist[].kind` | manufacturer/trader 칩 |
| `shortlist[].verified` | ⚓ 앵커검증 / 미검증(확산) 칩 |
| `shortlist[].capabilities[]` {code, evidence, basis} | HC/AF 역량 + 증거수준(L1~L3) — `.lv` 툴팁 |
| `shortlist[].score` + `breakdown[]` | 점수 + 항목별 가점 사유(설명가능) |
| `shortlist[].sources[]` | 출처 소스(factorion·made_in_china·web_search) |

존 분리: JSON에 이미 외부 공개 필드만 있음(내부 단가·품목코드·현협력사명 없음) →
`_result_row`가 보장. 콘솔도 그대로 노출 가능.

## 구현 (append-only, 기존 로직 무변)

1. `#longEvidence` 카드 마크업 추가(s-long, `#longNext` 위, 처음 hidden).
2. `<script>`에 파이프라인 결과 상수 `PIPE_RESULT`(JSON 임베드) + `renderEvidence()`.
3. `runLong()` 말미에 `renderEvidence(); $('#longEvidence').hidden=false;`.
4. 팔레트·클래스 재사용(.card/.ch/.chip/.lv/.mono/.tbl-wrap), 신규 CSS 0건 목표, 노랑 금지.
