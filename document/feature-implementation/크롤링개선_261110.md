# 상세 수집(크롤링) 개선안 — 2026-11-10

PMMA 라이브 실행(전체 535초)에서 상세 수집 대상 23곳이 **전부 수집 실패**했다. 그 결과 설비·인증 항목이
모두 '정보 없음'이 되어 점수가 낮게 몰렸고, 특허 제목이 있는 업체만 공정 근거를 얻어 숏리스트를 독식했다.

## 1. 실패 원인 분해

| 유형 | 건수(대략) | 실제 원인 | 성격 |
|---|---|---|---|
| `403 Forbidden` | 다수 | 실행 환경(클라우드 세션)의 네트워크 정책이 임의 외부 사이트를 차단 | 환경 |
| `Name or service not known` | 다수 | 공장등록 `hmpadr`의 낡은/잘못된 도메인 + 차단 환경에서의 DNS 실패 혼재 | 데이터 + 환경 |
| 홈페이지 오선정 | 2건 확인 | 채용공고(incruit), 계열사 사이트(lgls.co.kr = LG화학 생명과학) 채택 | 로직 |
| 근거 없는 판정 | 1건 확인 | 수집 실패인데 엘지전자에 '설비·제품 사양 확보 L2', 'ISO 9001 L3' | 로직(LLM) |

환경 문제는 사내 PC(제한 없는 네트워크)에서는 대부분 사라진다. 하지만 실서비스에서도 봇 차단·JS 렌더링·
낡은 도메인은 그대로 남으므로, **"홈페이지를 못 열어도 근거를 모으는" 구조**가 필요하다.

## 2. 개선 구조 — 근거 수집 사다리

한 소스에 의존하지 않고, 위에서부터 시도해 **근거 텍스트를 모은다**. 각 근거에는 출처 URL·수집 방식을 붙인다.

```
① 홈페이지 확정 (검증된 도메인만)
② 직접 크롤 (httpx)            ─ 실패(403·봇차단·JS) ─▶ ③
③ 렌더링 크롤 (Playwright)      ─ 실패/차단 환경 ──────▶ ④
④ 검색엔진 경유 근거 수집 (SerpApi, 사이트 접속 불필요)
⑤ 공개 문서 (카탈로그·인증서 PDF — 검색으로 찾은 filetype:pdf)
⑥ 그래도 없으면 '확인 불가' → RFI 질문 항목으로 넘김
```

### ① 홈페이지 확정 규칙 (오선정 차단)
- **차단 도메인 목록**: 채용(incruit, saramin, jobkorea, wanted), 기업정보(nicebizinfo, catch, jobplanet),
  마켓(coupang, 11st, alibaba 등), 뉴스·블로그·위키. 목록은 YAML 설정으로 관리.
- **이름 대조**: 후보 페이지 `<title>`·첫 화면 텍스트·footer(상호·사업자번호·주소)에 회사명(정규화)이 있어야 채택.
  공장등록 주소의 시·군·구가 footer 주소와 맞으면 가점.
- **계열사 구분**: 도메인 이름이 회사명과 다르면(예: lgls ≠ lgchem) 채택 전에 이름 대조를 필수로.
- **공장등록 hmpadr 우선이지만 검증 후 사용**: DNS 실패·리다이렉트로 다른 회사 사이트로 가면 버리고 웹검색으로.

### ② 직접 크롤 (현행 유지 + 보완)
- 메인 + 링크 텍스트 기준 우선 페이지(회사소개·설비·인증·제품·R&D)만 최대 N장.
- 실패 사유를 `blocked / dns / timeout / http_4xx / robots`로 분류해 기록(현재는 예외 문자열만 남음).

### ③ 렌더링 크롤
- ②가 빈 본문(JS 앱)·403(봇 차단)일 때만 Playwright로 재시도. 비용이 커서 상위 N곳에만.

### ④ 검색엔진 경유 근거 수집 ★ 핵심
홈페이지에 못 들어가도 검색엔진은 이미 그 페이지를 읽었다. SerpApi(현재 환경에서 접속 가능)로:
- `site:{도메인} 설비 OR 장비 OR 코터 OR 클린룸`
- `site:{도메인} ISO 9001 OR 인증`
- `"{회사명}" 하드코팅 OR 내지문 OR AF 코팅`
결과의 제목·스니펫·URL을 근거 텍스트로 쓴다. 증거 수준은 **L1(웹 언급)** 으로 상한을 둔다
(스니펫만으로 설비 사양을 확보했다고 볼 수 없으므로). 질의 수는 업체당 2~3회로 제한.

### ⑤ 공개 문서
- `site:{도메인} filetype:pdf 카탈로그 OR 인증서` → PDF는 `get_bytes`·pypdf로 파싱(기존 기능 재사용).
- 인증서 PDF에서 인증 번호·유효기간을 읽으면 L3.

### ⑥ 확인 불가 → RFI
- 근거가 끝내 없는 항목은 감점하지 않고 '확인 필요'로 남기고, RFI 회신 요청 항목에 자동으로 넣는다(현행 원칙 유지).

## 3. 판정 신뢰성 — 근거 없는 판정 막기

- **근거 인용 의무**: 판정 LLM 출력에 `quote`(근거 원문 일부)와 `source_url`을 필수로. 코드에서 quote가 실제
  수집 텍스트에 있는지 확인하고, 없으면 그 판정을 `unknown`으로 내린다.
- **증거 수준 상한(규칙)**: 수집 방식별 최대 수준을 코드로 강제한다.
  - 생산품명·업종명만 → 최대 L1
  - 검색 스니펫 → 최대 L1
  - 홈페이지 본문(설비 사양·사진·제품 사양) → 최대 L2
  - 특허 등록·인증서 PDF·시험성적서 → L3
- **특허 근거 보정**: 특허 '제목'은 기술 보유 근거지 양산 공정 근거가 아니다. 현재 특허 제목만으로 HC·AF가
  L2 met이 되어 특허 보유 대기업(엘지전자·엘지화학)이 상위에 오른다. 특허만 있으면 최대 L1(또는 별도 '기술 보유'
  표시)로 두고, 공정 L2는 홈페이지·카탈로그 근거가 있을 때만 준다.

## 4. 함께 고칠 버그 (이번 실행에서 확인)

- `enrich_patents`: 보강 대상 23곳 중 특허 확인 0곳. 특허 경로로 들어온 업체까지 0이라 회사명 정규화 대조 오류로
  추정 → 재현 테스트 후 수정.
- 같은 회사 여러 공장 중 무관한 공장(엘지화학 익산 의약품 공장) 선택 → 생산품 관련성으로 대표 공장 선택.

## 5. 기대 효과와 검증 방법

- 지표: 상세 수집 성공률(근거 1건 이상 확보 업체 비율), 항목별 unknown 비율, 홈페이지 오선정 건수,
  quote 검증 탈락 건수.
- 검증: PMMA 실행을 (a) 현 환경 (b) 제한 없는 네트워크에서 각각 돌려 위 지표를 비교. 현 환경에서도 ④ 덕분에
  성공률이 0%에서 올라가야 한다.

## 6. 구현 순서 (제안)

1. 실패 사유 분류 로깅 + 홈페이지 확정 규칙(차단 목록·이름 대조) — 작고 효과 큼
2. 판정 근거 인용 의무 + 증거 수준 상한 — 근거 없는 판정 제거
3. ④ 검색엔진 경유 근거 수집 — 차단 환경에서도 근거 확보
4. ③ 렌더링 재시도, ⑤ PDF 검색
5. `enrich_patents` 버그, 대표 공장 선택
