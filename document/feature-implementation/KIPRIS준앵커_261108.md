## 요약

26.11.07 서비스 점검으로 미뤘던 KIPRIS 앵커를 추가했다. 사용자가 발급한 KIPRIS Plus
API 키로 라이브 검증 후, 팩토리온과 동일한 1계층(structured) 패턴으로 붙였다.

## 엔드포인트 확정 (라이브 프로브)

- **서비스**: 특허·실용신안 서지정보 — `getAdvancedSearch` (출원인명 검색)
- **URL**: `http://plus.kipris.or.kr/kipo-api/kipi/patUtiModInfoSearchSevice/getAdvancedSearch`
- **인증**: `ServiceKey`(대문자) 파라미터. `applicant=회사명` + `numOfRows`/`pageNo`.
- **응답**: XML. `./header/{successYN,resultCode}`, `./body/items/item/*`, `./count/totalCount`.
- 반환 필드: `applicantName`, `inventionTitle`, `ipcNumber`, `registerStatus`,
  `applicationNumber`, `astrtCont`(요약). → 삼성디스플레이·코팅코리아 등으로 확인.

> 참조: https://plus.kipris.or.kr/portal/data/request/apiFsmtmList.do?menuNo=290005

## 설계상 위치: 앵커가 아니라 "준앵커"

STEP_1-1 설계 그대로. **팩토리온이 앵커, 특허는 팩토리온에 조인되는 준앵커.**

| | 팩토리온(강앵커) | KIPRIS(준앵커) |
| --- | --- | --- |
| 얻는 것 | 주소·공장번호·생산품목 | 출원인명·특허 제목·IPC |
| 식별 확정 | `verified=True` | `verified=False` (주소·사업자번호 미제공) |
| 역할 | 제조사 확정·흡착 기준점 | 특허 보유·기술분야 **근거 보강** |
| 매칭 실패 | 해당 없음 | 감점 아님 ('근거 없음'일 뿐) |

**중요(설계 문서와의 차이, 투명 보고)**: STEP_1-1은 KIPRIS에서 출원인 **주소**를 얻어
팩토리온과 주소 조인하는 걸 상정했으나, 이 서지검색 API에는 출원인 주소가 없다
(출원인명·발명명칭·IPC·상태만). 주소 조인용 출원인정보 API는 현재 파라미터 오류로
막혀 있어, KIPRIS는 주소 확정 없이 "특허 보유 + 기술분야" 근거만 제공하는 준앵커로
확정했다. 역량 판정(HC/AF)은 기존대로 LLM classify가 수행한다.

## 추출기 (`KiprisExtractor`, tier=1)

- `query={'company': 출원인명, 'rows': N}` → 출원인명 검색.
- **한 출원인의 특허 다건을 1개 `SupplierRecord`로 집계**(출원인 = 기업 1개).
- `products`에 특허 제목(대표 5건) → classify가 기술분야로 해석.
- `notes`에 `[특허] 제목` + `[IPC] 상위분류`(중복제거) → 역량 근거.
- `provenance.note`에 `특허 N건 보유`(totalCount). `verified=False`.
- 특허 없는 출원인(가공업체 등) → 빈 리스트(정상). `verify()`로 일괄 조회.

## 파이프라인 합류 (`enrich_patents`)

새 후보를 만들지 않는다 — 준앵커라 기존 레코드(팩토리온 앵커 + 확산 잔여)에 특허
근거를 **보강**만 한다.

```
[anchor_merge]  팩토리온 흡착 → verified 승격
     v
[enrich_patents] KIPRIS 조회 → 정규화 회사명 일치 레코드에 특허 제목·IPC·prov 누적
     v           (merge_into 재사용. 매칭 실패는 그냥 근거 없음·감점 아님.)
[classify]      특허 제목·IPC가 L3 역량 근거로 들어감
```

- `run(..., live=True | enrich=True)`일 때만 호출(API 호출이라 오프라인 데모 재생 시 off).
- `_norm_name`으로 회사명 매칭(법인격·공백 흡수). 주소 미제공이라 `verified`는 안 올림.

  정상 로드. 단 인자 없는 `load_dotenv()`는 이 환경에서 `find_dotenv()`가 CWD를
  못 찾아 주입 실패 → **`load_dotenv(".env")` 명시 경로** 권장(KIPRIS·OPENAI 공통).
