## 요약

팩토리온(한국산업단지공단 공장등록 생산정보) OpenAPI를 **실제 호출**해 응답 구조를
확인하고 1계층 추출기를 구현했다. 그 과정에서 당초 가정과 다른 사실 세 가지가
드러나 설계를 교정했다.

## 1. 사내망 TLS 가로채기 해결 (전체 전제)

회사 네트워크가 자체 서명 CA로 HTTPS를 가로채, pip뿐 아니라 모든 Python 요청이
`CERTIFICATE_VERIFY_FAILED`로 막혔다.

- 해결: **`pip-system-certs`** 설치 → Python이 Windows 인증서 저장소(사내 CA 포함)를
  자동 신뢰. 이후 모든 실제 API·크롤링 호출 성공. requirements.txt에 반영.
- fetcher는 추가로 `SOURCING_CA_BUNDLE`(PEM 경로)·`SOURCING_SSL_VERIFY=false`
  환경변수 훅을 둬, 다른 환경에서도 대응 가능하게 했다.

## 3. 설계 교정 — "발견 소스"가 아니라 "검증 앵커"

실데이터로 드러난 세 가지:

1. **회사명 부분일치 검색만 지원.** 생산품으로는 검색되지 않는다. "광학"으로 치면
   안경·현미경·부동산임대까지 섞여 나온다.
2. **주생산품 표현이 제각각.** "안경렌즈가공", "렌즈,프리즘" 등 자유어 → 공정 역량
   키워드 매칭(하드코팅/내지문)은 실효성이 없다.
3. **사업자등록번호 필드가 없다.** 대신 `fctryManageNo`(공장관리번호)가 식별키.

→ 결론: 팩토리온은 **발견(discovery)이 아니라 검증(verification) 앵커**다.
확산 소스(웹검색·디렉터리)가 찾은 **회사명 후보**를 넣어 주소·공장·생산품을
교차검증하는 데 쓴다. 이는 데모의 "앵커 흡착" 설계와 정확히 일치한다.

### 코드 반영

- `verify(companies: list[str])` 메서드 추가 — 회사명 리스트 일괄 검증.
- **키워드 매칭(`PROCESS_KEYWORDS`) 제거.** 동작하지 않는 투기적 코드라 삭제.
  공정 역량(HC/AF) 판정은 **LLM 계층**이 담당(Task #14).
- `has_factory=True`·`kind=MANUFACTURER`·`provenance.verified=True`로 "확정 제조사" 표식.

### 실데이터 버그 수정

`hmpadr`에 주소 조각("75번길 22아파트") 등 비URL 쓰레기가 섞여 pydantic URL 검증이
깨졌다. `_looks_like_url`(공백 없음 + 도메인에 점 포함)로 걸러 URL 형태만 수용,
아니면 `None`(홈페이지 미상).
