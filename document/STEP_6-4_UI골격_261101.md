## 결정 1 — 좌측 레일 → 상단 가로 GNB

기존 좌측 프로세스 레일을 **상단 가로 메뉴바(GNB)** 로 전환합니다(피드백 4). 라이프사이클 대분류로 그룹화하고 구분선으로 국면을 나눕니다.

```
[ SDC Sourcing Agent ]   접수 │ 발견·검증 │ 컨택 │ 분석 │ 실행        [역할 ▾]
```

| 그룹 | 메뉴 | 대응 단계 |
| --- | --- | --- |
| 접수 | 소싱 요청 | STEP_6-1 |
| 발견·검증 | 스펙 · 롱리스트 · 상세수집 · 숏리스트 | STEP 0~3 |
| 컨택 | RFI 발송·회신 | STEP_6-2 |
| 분석 | 연계분석 · 브리프 | STEP 4~5 |
| 실행 | 소싱 실행 추적 | STEP_6-3 |

- **대시보드(재협상 대상 품목)** 는 GNB 좌측 "홈/현황"으로 유지.
- 활성 탭은 **블루 언더라인**, 비활성은 회색.

### 팔레트 치환 (중요)

레퍼런스 메뉴바는 네이비 + **노랑(amber)** 강조를 쓰지만, 우리는 이미 확정한 팔레트로 치환합니다:

| 레퍼런스 | 우리 적용 |
| --- | --- |
| GNB 배경 네이비(#1e293b) | 블랙 계열(`--fg`) |
| 활성 탭 노랑/하늘 | 블루(`--accent`) 언더라인 |
| amber 뱃지(고도화 등) | 하늘색(`--warn`) 또는 블루 |
| 카운트 뱃지 빨강 | 레드(`--bad`) 유지 (알림 성격) |

**노랑은 쓰지 않습니다.** 강조=블루/레드, 기본=블랙·화이트, 보조=회색/하늘색.

## 결정 2 — 프로세스 진행 현황 스텝퍼

GNB 바로 아래에 **가로 스텝퍼**를 상시 노출해, 현재 소싱 건이 전체 흐름 중 어디인지 보여줍니다(피드백 5, 레퍼런스 이미지).

```
접수 ▸ 스펙 ▸ 롱리스트 ▸ 상세 ▸ 숏리스트 ▸ RFI ▸ 분석 ▸ 브리프 ▸ 실행
                              ●현재
```

- 현재 단계는 블루 강조, 완료는 체크, 미도달은 회색.
- 기존 데모의 레일에 있던 "내부망 전달 범위" 경계 표시는 스텝퍼에서 **컨택↔분석 사이 경계선**으로 계승(존 분리 가시화 유지).
- 구현상 레퍼런스 SRM의 `flow-strip` 패턴과 동일 — 단계 배열 + 현재 인덱스 강조.

## 결정 3 — 역할 전환

레퍼런스의 role-switcher를 도입합니다. 우측 상단 드롭다운.

| 역할 | 보이는 것 |
| --- | --- |
| 요청자(수요부서) | 소싱 요청 작성/제출, 자기 요청 상태 조회, 결과(브리프 요약) 열람 |
| IPC(소싱 담당) | 전 단계. 요청 접수, 소싱 실행, RFI 관리, 분석, 실행 추적 |
| (열람) | 읽기 전용(선택) |

- 역할에 따라 GNB 메뉴 노출/비노출, 액션 버튼 활성/비활성이 바뀝니다.
- PoC는 "보이는 화면/액션" 구분까지. 서버 권한 검증은 생략(STEP_6 트레이드오프).
- 기존 헤더에서 제거했던 "담당자명"은 역할 전환 드롭다운으로 대체되는 셈.

## 결정 4 — 기존 자산 승계

- 존 태그(외부 수집 영역/내부망): GNB 하단 또는 스텝퍼 경계로 계승.
- 코드/소스/출처 **툴팁**: 그대로 유지.
- 블랙 primary 버튼, 하늘색 info, 차트 블루/블랙: 그대로.
- Samsung Sharp Sans(→Poppins 폴백) 브랜드 폰트: GNB 로고타입에 적용.

## 전환 비용·주의

- 좌측 레일 → 상단 GNB는 **네비게이션·레이아웃의 큰 리팩터링**입니다. 화면(section) 자체는 재사용하되, 셸(shell) 그리드와 네비 생성 로직을 교체합니다.
- 신설 3단계 화면이 더해지므로 GNB 항목이 길어집니다 → 그룹 구분선 + 가로 스크롤(레퍼런스 `.gnb-menu` overflow 패턴)로 수용.

## 데모 반영 범위

- **실제 동작:** 상단 GNB(그룹·활성 언더라인), 프로세스 스텝퍼(현재 단계 강조), 역할 전환(메뉴/액션 가변), 팔레트 치환.
- **자리만 확보:** 열람 전용 역할, GNB 알림 카운트 실데이터.
