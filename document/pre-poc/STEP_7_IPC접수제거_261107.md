## 배경

시연 대상 고객사인 삼성디스플레이(SDC)가 사내 IPC(소싱 전담 조직)와 관계가 불편하다는
임원 피드백이 있었습니다. IPC가 전면에 드러나는 데모는 고객사에 거부감을 줄 수 있어,
**IPC 및 접수(소싱 요청 창구) 관련 내용을 데모에서 제거**하기로 했습니다.

기존 버전의 품질은 유지 가치가 있으므로, **원본(`_261101`)은 보존하고 개선 버전(`_261107`)을
별도 파일로 분기**해 작업했습니다.

## 제거 의사결정의 논리

지시의 핵심은 단순히 "IPC"라는 용어 삭제가 아니라 **"IPC가 소싱을 대행한다"는 업무 모델
자체를 걷어내는 것**으로 해석했습니다.

- **접수 화면**은 "요청자(수요부서)가 IPC에게 소싱을 올리고 IPC가 받아 처리한다"는
  **요청자↔IPC 분업**을 전제로 설계된 화면입니다. IPC를 지우면 접수의 존재 이유도 사라집니다.
- **역할 전환**(IPC·요청자·열람 3역할)도 동일한 분업 모델의 산물입니다. IPC가 없으면
  역할 개념 자체가 무의미해집니다.

따라서 제거의 논리적 단위는 **"IPC 중심 분업 모델" 하나**이며, 접수·역할전환이
모두 여기에 종속되어 함께 제거됩니다.

반면 **RFI 컨택**은 "회사가 숏리스트 업체에 정보요청을 발송·회신분석"하는 중립적 기능이라
IPC 조직과 무관합니다. 따라서 **화면·흐름은 보존하고 IPC 색채(용어)만 제거**했습니다.

## 결정 사항

| # | 결정 | 근거 |
| --- | --- | --- |
| 1 | 역할 전환 **전체 제거** | 3역할은 IPC 분업의 산물. IPC 부재 시 무의미 |
| 2 | 접수 화면 `s-intake` **전체 제거** | "요청자가 올리고 IPC가 접수"가 화면의 존재 이유 |
| 3 | RFI 화면 **유지 + IPC 색채만 제거** | 기능 자체는 조직 중립적 |

## 변경 전/후 라이프사이클

```
[변경 전] 5국면 (트리거 이원화)
  접수(수동요청)  →  발견·검증  →  컨택  →  분석  →  실행
  + 자동진단(dash)

[변경 후] 4국면 (자동진단 단일 트리거)
  현황(dash) → 발견·검증(STEP0~3) → 컨택(RFI) → 분석(STEP4~5) → 실행
```

접수 단계가 빠지면서 트리거가 **자동 진단(재협상 대상 품목) 단일**로 정리되었습니다.
GNB 그룹: 현황(1) · 발견·검증(4) · 컨택(1) · 분석(2) · 실행(1) = 9단계.

## 코드 변경 내역 (`_261107.html`)

### 제거

- **상단 역할 셀렉트** (`#roleSel` 마크업 + `.role` CSS 규칙)
- **`s-intake` 섹션** 전체 마크업 (소싱 요청서 폼 · 유사 자재 추천 · 접수함)
- **접수 JS 블록** 전체: `PURPOSES` / `MAT_MASTER` / `SIMILAR` / `INBOX` / `ST_INTAKE` /
  `fillSpec` / `renderSimilar` / `renderInbox` / `INITS.intake` 및 모든 이벤트 핸들러
- **`STEPS`의 `intake` 항목** + 전 단계의 `roles` 속성
- **역할 시스템 로직**: `role` 변수, `ROLE_LABEL`, `renderGnb`의 역할 필터,
  `go()`의 역할 가드, `#roleSel` change 핸들러(역할 재렌더 훅 포함)

### 중립화 (유지하되 IPC 색채 제거)

- RFI 무응답 조치 버튼: `IPC 승인 · 조치 실행` → `승인 · 조치 실행`
- exec 실행 추적: `isIpc` 노출 게이팅 제거 → 동기화·담당자 확정 버튼 **항상 노출**

### 보존 (조직 중립적이라 그대로 둠)

- RFI 화면 전체 구조 · 컨택 포인트 발굴 · 회신 등급 승급
- RFI 발신자 표기 "삼성디스플레이 구매팀" (회사 주체이지 IPC 조직 지칭 아님)
- 존 분리 · 사람 확인 지점 · 개인정보 비저장 · ERP 쓰기 제외 등 기존 4원칙
