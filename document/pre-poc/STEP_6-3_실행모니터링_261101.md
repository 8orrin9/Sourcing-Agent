# 실행 — 소싱 실행 추적

작성일: 2026-11-01
상위 문서: [STEP_6_업무확장설계_261101.md](STEP_6_업무확장설계_261101.md)

## 문제

소싱(업체 발굴·선정)이 끝나도 **곧장 대체·발주로 이어지지 않습니다.** 현장 피드백:

- 내부 업무 프로세스상 소싱 이후 **견적 → 방문 → 테스트 연계** 등 여러 단계를 거칩니다.
- 이 과정을 **모니터링·관리**할 수 있어야 합니다(수개월이 걸리는 현실이 보여야 함).

## 결정 1 — 실행 스테이지 정의

소싱 확정(브리프/RFP 이후) 건을 **실행 파이프라인**으로 넘겨 스테이지별로 추적합니다.

| 스테이지 | 내용 | 산출물 |
| --- | --- | --- |
| 견적 | 정식 견적 요청·수령 | 견적서, 공정 단가 분해 |
| 방문·심사 | 현장 실사(STEP 3의 "현장 확인 필요" 태그와 연결) | 실사 체크리스트, 사진 |
| 샘플·테스트 | 샘플 수령 → 품질·신뢰성 테스트 | 테스트 성적, 합부 판정 |
| 승인·등록 | 협력사/품목 승인, 시스템 등록 | 승인번호, 등록 완료 |

각 스테이지는 상태(예정/진행/완료/보류)와 예정일·담당자를 가집니다.

## 결정 2 — 가시화: 업체별 타임라인

"즉시 대체 불가"라는 현실을 **시간 축**으로 보여줍니다.

- **타임라인/칸반:** 업체(또는 소싱 건)별로 스테이지 진행을 가로 타임라인 또는 칸반으로 표시. 수개월 소요가 한눈에 보이도록.
- **STEP 3 연계:** 숏리스트에서 "현장 확인 필요" 태그가 붙은 업체는 방문·심사 스테이지로 자동 승계 — 미확인 정보가 실행 단계에서 해소되는 경로.
- **브리프 연계:** 브리프의 대체 공급원(BATNA)이 실제 실행 파이프라인에 올라가면서, "두 번째 공급사"가 현실의 승인 절차로 전진.

## 결정 3 — 지연 알림

- 스테이지 예정일 경과 시 지연 표시, 담당자에게 알림(STEP_6-2 에스컬레이션과 동일한 설정 기반 방식).
- **자동 전진 금지:** 스테이지 전환은 담당자 확정으로만(테스트 합부 등은 사람 판단). 에이전트는 상태 요약·지연 경보·다음 할 일 제안만.

## 에이전트/코드 분업

- **에이전트:** 각 스테이지 산출물(견적서·테스트 성적) 요약, 다음 액션 제안, 지연 사유 서술.
- **코드:** 스테이지 상태 전이 규칙, 예정일 경과 판정, 타임라인 렌더링 데이터.

## 데이터

`ExecutionStage`(STEP_6 데이터 모델): SourcingRequest 참조, 스테이지, 상태, 예정일, 담당자. 모든 산출물은 Document/Evidence로 연결해 역추적.

## 데모 반영 범위

- **실제 동작:** 소싱 완료 건의 실행 타임라인(견적→방문→테스트→등록) 상태 표시, 지연 경보, STEP 3 "현장 확인 필요"에서의 승계.
- **자리만 확보:** 실제 테스트 데이터 연동, ERP 등록 쓰기(STEP_0 "범위 밖: ERP 쓰기"와 정합 — 등록은 "제안/표시"까지).
