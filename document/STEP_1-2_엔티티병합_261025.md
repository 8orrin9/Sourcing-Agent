# 엔티티 병합 규칙 — 결정 및 핵심 내용

작성일: 2026-10-25 · 상위 문서: [STEP_0_구현설계서_261025.md](STEP_0_구현설계서_261025.md) · 관련: [STEP_1-1_탐색설계_261025.md](STEP_1-1_탐색설계_261025.md)

서로 다른 소스에서 나온 레코드가 같은 회사인지 판단하고 하나로 합치는 규칙입니다. "②번 급소 — 이름→사업자번호 해소"가 실제로 풀리는 지점입니다.

## 문제: 필드 비대칭

- 앵커 소스(공장등록·특허) → 사업자번호·주소 보유
- 확산 소스(웹·B2B·전시회) → 회사명·URL만 (사업자번호 없음)
- → 한 번에 단일 키로 병합 불가. 2단으로 나눔.

## 1단: 앵커 확정 병합 (강한 키)

| 키 | 강도 | 동작 |
| --- | --- | --- |
| 사업자번호 | 결정적 | 일치 = 무조건 동일 회사 |
| 법인등록번호 | 결정적 | 상동 |
| (특허) 출원인코드 → 팩토리온 주소 대조 | 준결정적 | 일치 시 사업자번호 부여 |

→ 결과물: 사업자번호가 박힌 **확정 엔티티(골든 레코드)** 집합. 병합의 중심.

## 2단: 확산 레코드 흡착 (약한 키 + 점수)

확산 레코드(회사명/URL만)를 확정 엔티티에 붙임. 단일 키 불가 → 신호 점수화.

| 신호 | 가중 | 비고 |
| --- | --- | --- |
| 도메인 일치 (웹 URL ↔ 공식 도메인) | 강 | 가장 신뢰 높은 약한 키 |
| 정규화 상호명 일치 | 중 | `(주)`·`㈜`·`Co.,Ltd` 제거, 공백·대소문자 정규화 |
| 상호명 유사도 (편집거리/토큰) | 약 | 부분일치 ("서진코팅" vs "서진코팅테크") |
| 주소 지역 일치 (시·군·구) | 약 | 보강 |
| 전화번호 일치 | 중 | B2B 디렉터리에 종종 존재 |

### 임계값 3구간

- **자동 병합:** 도메인 일치 **또는** (정규화 상호명 일치 + 지역 일치)
- **검토 큐:** 상호명만 중간 유사 — 사람 확인 또는 STEP 2 후 재판정
- **분리 유지:** 신호 부족 — 독립 후보로 남김

## 급소 해소: 사업자번호 상속

확산 레코드는 병합 시점에 사업자번호가 없어도 흡착 순간 앵커의 사업자번호를 **상속**받음.

```
웹 검색 "서진코팅" (사업자번호 없음)
   │ 도메인 일치
   ▼
팩토리온 확정 엔티티 "서진코팅(주)" (사업자번호 보유)
   │ 흡착 → 사업자번호 상속
   ▼
STEP 3에서 국세청·국민연금·DART 조회 가능
```

## 흡착은 2회 발생 (결정)

순수 웹 후보(앵커 미흡착·사업자번호 미확보)도 **STEP 2 크롤링까지 동등 대우 후 재판정**.

1. **1차 흡착 (STEP 1):** 도메인·정규화 상호명 기준.
2. **2차 흡착 (STEP 2 크롤링 후):** 크롤링으로 드러난 도메인·사업자번호·사업자등록증으로 앵커에 재흡착.
3. 2차에서도 미흡착 → "사업자번호 미확보·현장 확인 필요" 태그 (감점 아님, 설계서 STEP 3 기조와 일치).

→ 영세 제조사를 살리는 방향. 데모 '청우코텍'(웹 정보 부족 → 현장 확인 대상) 케이스를 설명.

## 상충 처리 (필드별 신뢰 우선순위)

한 확정 엔티티에 소스가 모순될 때(예: 본사 주소 vs 공장 주소) 덮어쓰지 않고 소스별 Evidence로 병존. 필드별 우선순위:

- 주소·생산품목: **공장등록 > 웹** (공적 등록 우선)
- 설비·공정 역량: **웹/카탈로그 > 공장등록** (등록엔 설비 디테일 없음)
- 재무: **DART > 기타**

→ 데이터 모델 `Site`(본사/공장 분리)·`Evidence`와 연결.

## 미해결·후속

- 정규화 규칙·유사도 알고리즘 종류 — 구현 디테일(기본값 처리).
- STEP 3 공공 DB 검증 설계 — 별도 논의.
